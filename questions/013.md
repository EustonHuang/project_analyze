# Q13 — agent-trace-view 打开 127.0.0.1:8765 返回 404，为什么？

## 现象
调用 agent-trace-view skill 启动 viewer 后，浏览器访问 http://127.0.0.1:8765
返回 404 "File not found"。即使 server 进程确实在运行，也一样 404。

## 根因
`server/server.py` 第 14–15 行：

```python
ROOT = os.path.dirname(os.path.abspath(__file__))   # .../agent-trace-view/server
WEB  = os.path.join(ROOT, "web")                     # .../agent-trace-view/server/web
```

`ROOT` 是 `server/` 目录本身，因此 `WEB` 指向 `server/web/`。
但前端文件实际位于 **`server/` 的同级** `agent-trace-view/web/`（index.html / styles.css / app.js）。

`Handler` 用 `SimpleHTTPRequestHandler(directory=WEB)` 从该目录取静态文件；
`server/web/` 不存在 → `list_directory` 抛 `FileNotFoundError` → 返回 404。

与端口是否在监听、trace 文件是否存在无关——server 跑起来也因无前端可服务而 404。

## 验证
- `list_dir .codebuddy/skills/agent-trace-view/web`：index.html / styles.css / app.js 均存在。
- `server/web/` 不存在（磁盘上只有 `server/server.py`）。
- 注：`history/021.json` 曾声称创建了 `web/index.html` 等，文件确实在 `agent-trace-view/web/`，
  只是 server.py 的 WEB 路径算错，并未真正服务到。

## 修复方向
`WEB` 应改为 `os.path.join(os.path.dirname(ROOT), "web")`
（即 server 的父目录 + web），或 `Path(__file__).resolve().parent.parent / "web"`。
