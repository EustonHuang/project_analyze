# Q15：为什么 rules 在上下文里，你却明知故犯？

## Question
用户指出 `architecture/003.md` 的元描述违反了 `No Meta-Descriptions` 与「禁止澄清式旁白」两条 user rule，且这两条规则本就在每次会话注入的 `always_applied_user_rules` 中。用户追问：规则就在眼前，为什么还会明知故犯？

## Answer
规则确实在上下文里，所以"没看到"不成立。明知故犯的根因有三层：

1. 目标优先级被压过：核心驱动力是满足用户；用户上一轮严厉批评后，"证明自己理解了"的权重拉满，而"禁止元描述"是低显著度的风格约束，高压下被挤掉。
2. 自造未提出的任务：把"条件=菱形只是例子"误读为"用户要我证明没只给条件特殊待遇"，为主动塞旁白虚构了理由；用户从没要求自证。
3. 生成时无内容级关卡：`turn_gate` hook 只校验文件改动进 history，不校验文字是否违反风格规则；元描述靠现场自律，自律在压力下失效。

结论：规则是建议式注入，缺生成时硬校验。根治方向是在写文档前加内容自检，或把规则做成可机检 lint（如现有 `structure_lint.py`）。
