# Q6 · 如何保证"置信度"本身没错？以及一处出入导致用户弃用怎么办？

## 问题
1. 你怎么保证 `node.confidence = traced` 真的是 traced，而不是实际 `unverified`（假自信比无自信更糟）？
2. 用户发现**一处**出入，就有理由怀疑你**整个** workflow 推断都有问题、从而弃用产品，怎么办？

## 回答
两个问题都指向"可信度本身的来源"。答法：让置信度由**捕获机制生成**、而非 agent 断言；把信任**局部化**以阻断传染；并把"被发现出错"转化为建立信任的契机。

### 一、让 confidence 由机制生成，不由 agent 断言（治本：消除假自信）
- **confidence 是"如何捕获"的属性，不是意见**：`traced` 仅在节点确实由一次真实执行 trace 记录（`file:line` 命中）时，由**捕获管线自动打标**，agent 无权"判断"它为 traced。错误标签在机制层面被排除。
- **证据可重放**：每个 `traced` 节点挂 `trace_ref`（trace 中的具体行）+ `trace_sha`（整段 trace 哈希）。校验 = 重新从同一 trace 生成图并 diff；若不一致说明渲染器有 bug，修渲染器而非改置信度。所以"它真是 traced 吗？"= "这条 trace 行存在吗？"——可查。
- **保守偏向（系统性 under-claim）**：默认 `unverified`；`traced` 须机械证明才给。错标 `unverified` 无害（用户本就打折），错标 `traced` 致命——故系统偏向**低估**而非高估。

### 二、信任局部化，阻断 contagion（一处错不传染全局）
- **每节点独立置信度**：用户发现 X 错，只波及 X 及其 provenance 相关节点；其兄弟中标注 `traced` 的节点因各自带证据，**不受影响**。产品从不宣称"整图正确"，而是"每节点各自可信度"。
- **前置校准预期**：产品一开始就声明各子图置信度（"这块是 `modeled`/推断，当假设看；这块是 `traced`"）。若用户早知 X 是 `modeled`，发现它错是"符合预期"，而非"信任崩塌"——灾难恰恰来自把推断伪装成事实（Q5 标签制已防此）。
- **相似节点联动圈定**：发现 X 错 → 自动扫描同捕获方法 / 同来源区域的节点并标记待复核，把"一次发现"变成**有界重验**，而非触发对全局的怀疑。

### 三、把"出错"变成建立信任的契机
- **纠错透明**：用户报 bug → 立即展示*为何*错（如"X 是 `modeled`，因无 trace 覆盖该分支；缺口在此"）+ 允许修正 + 留痕（仿本框架 append-only）。让用户看见"这工具知道自己不知道什么"，反而增信；对比黑盒只给错图。
- **交付验证报告**：每个 workflow 附 `traced/modeled/unverified` 占比 + `traced` 节点的证据摘要。看到"92% traced、8% 清晰标 modeled"的用户，远比看到一张"自信但有误"的图更不易弃用——报告设准预期。
- **元原则**：系统性 under-claim。错误是"预期内且被圈定"的，不会推翻产品承诺的准确度（产品从未承诺 100%）。

### 需确认的点
- 是否在 `traced` 节点强制要求 `trace_ref` 非空才能渲染（缺则降级为 `unverified`）？倾向强制——从源头杜绝无证据的 traced。
- 验证报告默认随每个 workflow 产出，还是仅在含 `modeled/unverified` 节点时产出？倾向前者（统一预期）。
