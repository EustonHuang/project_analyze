# 问题：流程图（agent-trace-view 中的 Flow Graph）到底是什么？

## 问
流程图到底是什么？它在这个项目里指什么、由什么构成、当前实现到什么程度？

## 答（定义）
流程图是 `agent-trace-view` 用 **Cytoscape.js** 把 trace 的**控制流（control flow）画出来的一张有向图**——它**不是层级树**，而是对执行顺序/分支的可视化。

### 数据来源
- 读取 `agent_traces/*.json`（默认 `project_analyze_flow.json`）的 `phases[]` 与各 `nodes[]`。
- `buildGraph()` 把 `children`（下一步 sibling）、`yes_branch`/`no_branch`（决策分支）、`loop`（环）转成图的边；`renderGraph()` 交给 Cytoscape 渲染。

### 结构（关键，区别于层级树）
- **顶层 = 5 个顺序阶段** `P1→P2→P3→P4→P5`，彼此是 **siblings**，靠「阶段末节点的 children 指向下一阶段首节点」串成一条链。
- **阶段内部仍是 siblings**：
  - `P1` `kind=parallel`：s1/s2/s3 **并行**执行，互不相依。
  - `P2/P3/P4/P5` `kind=sequence`：节点靠 `children` **顺序**连接。
- **边 = 控制流转移**：下一步(children) / 决策分支(yes/no) / 环(loop)。

### 当前实现状态（截至 architecture/011）
- 默认**完整渲染全部节点与边**，不再折叠——因为 sibling 不是父子，不应折叠（architecture/010 的折叠做法是误判，architecture/011 纠正）。
- 入口：左侧面板「流程图」标签，与「步骤」树互相切换（非中间标签、非全屏覆盖层；architecture/010 已改回左侧）。
- 交互：滚轮缩放、拖拽平移、工具栏 +/−/适应窗口；点击节点 → 中间显示来源详情、右侧文件查看器定位到对应代码行。

### 已知缺口
- **P1-P5 目前没有渲染成图里的节点**，只用作左侧「步骤」树的分组标题。这是用户指出过、但尚未修复的缺漏（需把阶段渲染为可见的阶段框/分组）。
- 节点 `id`（`s1/n1/n10`…）命名混乱，无规范（见 questions/016、018）。
