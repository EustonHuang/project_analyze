# Q12 · 详细列出 ISO/IEC 25010

## 问题
详细列出 ISO/IEC 25010 标准（Q11 提议用它作为分类外部校验锚）。

## 回答
### 一、是什么 + 现行版本
- ISO/IEC 25010 是**系统与软件产品质量**及**质量使用**的模型标准，属 SQuaRE 系列（ISO/IEC 25000）。
- 现行版 **ISO/IEC 25010:2023**（2023-08 发布），替代 25010:2011；2023 把"产品质量"与"质量使用"合并同标准，并纳入数据质量（源自 25012）。
- 立场提醒：它仍是**人为共识模型**，不是"绝对真理"。Q11 的用法是"比我的直觉更稳的外部校验锚"，而非"它证明完备"。

### 二、产品质量模型（8 大特性 + 子特性）
1. **功能适合性 Functional suitability**
   - 功能完整性 Functional completeness
   - 功能正确性 Functional correctness
   - 功能恰当性 Functional appropriateness
2. **性能效率 Performance efficiency**
   - 时间特性 Time behaviour
   - 资源利用 Resource utilisation
   - 容量 Capacity
3. **兼容性 Compatibility**
   - 共存性 Co-existence
   - 互操作性 Interoperability
4. **可用性 Usability**
   - 可识别恰当性 Appropriateness recognizability
   - 易学性 Learnability
   - 可操作性 Operability
   - 用户错误防护 User error protection
   - 界面美观性 User interface aesthetics
   - 可访问性 Accessibility
5. **可靠性 Reliability**
   - 成熟度 Maturity
   - 可用性 Availability
   - 容错性 Fault tolerance
   - 易恢复性 Recoverability
6. **安全性 Security**
   - 保密性 Confidentiality
   - 完整性 Integrity
   - 抗否认性 Non-repudiation
   - 可追责性 Accountability
   - 真实性 Authenticity
7. **可维护性 Maintainability**
   - 模块化 Modularity
   - 可复用性 Reusability
   - 可分析性 Analysability
   - 可修改性 Modifiability
   - 可测试性 Testability
8. **可移植性 Portability**
   - 适应性 Adaptability
   - 可安装性 Installability
   - 可替换性 Replaceability

### 三、质量使用模型（quality-in-use，简述）
面向"特定用户在特定语境下使用产品达成目标"的效果：有效性 Effectiveness、效率 Efficiency、满意度 Satisfaction、风险自由 Freedom from risk、语境覆盖 Context coverage。

### 四、用 25010 校验 Q11 分类（映射表）
把追踪系统问题映射到 8 特性，看原四类漏了什么：

| 我们的分类 | 主要映射到 25010 |
|---|---|
| 采集完整性 | 功能适合性(完整性) + 性能效率(开销/容量) |
| 模型/表示 | 功能适合性(恰当性) + 兼容性(与 viewer 互操作) |
| 信任/保真 | 可靠性(成熟度/容错/恢复) |
| 生命周期/检索 | 可维护性(可分析/可改/可测) + 可移植性 |
| 发现/入门 | 功能适合性(完整性) + **可用性(易学/可识别)** |
| 可理解性 | **可用性(可操作/易学/美观/可访问)** ← 原四类漏 |
| 语义有效性 | 功能适合性(正确性) |
| 工具可运维 | 性能效率(资源/容量) + 可靠性(成熟度) |
| 治理/权限 | **安全性(保密/完整/可追责/真实)** ← 原四类漏 |

→ 结论：原"采集/表示/信任/生命周期"四类几乎只覆盖 功能适合性、性能效率、可靠性、可维护性、可移植性；**系统性漏掉"可用性 Usability"与"安全性 Security"两特性**，而 Q11 找到的两大逃逸类（可理解性=可用性、治理=安全性）正落在这俩漏掉的特性上。外部框架验证了 Q11 的自我批判。

### 需确认的点
- 是否以此 8 特性作为分类**校验矩阵**（每加一类先归到某特性；若某特性下为空，主动追问"这类问题有没有"）？倾向是。
- 是否把"可用性""安全性"提为一级问题类？倾向提（直接对应你 Q1 原痛与治理需求）。
