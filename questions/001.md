# Q1 · 设计一个"项目执行流拆解与展示"工具

## 问题（用户背景与两个 case）

用户的痛点：很多时候想**系统、彻底**地了解一个项目/代码/架构"是怎么运转的"——先做什么、后做什么、入口在哪里、每一步之后又触发什么。难点在于：不知道入口、不知道入口后的步骤顺序、找步骤时容易迷失。

本项目的目标：做一个工具，把**任何项目的执行流程**拆解成结构化步骤，并清晰地展示给读者。

两个具体 case：
1. **AI Agent 运作流**：以 prompt 为起点，AI 触发一系列关联（rules / memory / hooks / skills…），每个触发都有条件（如 skills 仅当文本提到或经分析需要时才触发）。触发后的执行流程是什么？第一步、第二步……可能有并行、循环等。需要了解的是**整体 execute workflow**；记录时要记住每个细节（或用户设定 `depth` 参数控制下钻层数），但展示时可选择性详略——用户可展开细节、也可只看整体。
2. **代码执行流**：如 `python run_script.py + 参数`，从脚本开始逐步记录第一步跑什么、第二步跑什么；中途调用函数如何跑；异步、多进程/多线程各自跑什么。同样：**记时越详细越好，展示时详略得当（可展开/收起）**。

用户的诉求：请设计"如何实现这样一个把任何项目步骤拆解并展示给读者"的工具，并写入 questions。

## 设计提案（如何实现）

### 一、核心原则
- **capture-max / render-on-demand**：记录阶段全量捕获、保留所有粒度；展示阶段由读者决定展开多少。
- `depth` 参数控制下钻层数（概念模式限递归层；代码模式限调用栈深度或全收但折叠）。
- 记与展解耦——同一份全量数据，多种详略视图。

### 二、统一数据模型：Workflow Graph
- 单一归一化模型，让两个 case **共用同一个 viewer**。
- **节点** `node`：`id` / `parent` / `label` / `kind`（入口·触发·调用·并行分叉·循环·分支·IO·异步任务·进程/线程）/ `detail`（全量文本，按 max depth 写满）/ `depth` / `control`（顺序·并行·循环·条件）/ `meta`（`file:line`、触发条件、pid/thread 等运行时信息）。
- **边** `edge`：`from` / `to` / `type`（`next`·`parallel-member`·`loop-back`·`branch`·`spawn`）/ `order`。
- 常见形态以"树 + 回边"表达；循环/并行用可视化标记，不破坏主体顺序。

### 三、采集层（对应两个 case）
- **Mode A 概念/智能体流**：agent 驱动的结构化追问。给定入口（如 prompt），先列一级触发（rules/memory/hooks/skills…），每个触发再展开执行序列，按 `depth` 递归下钻，全量写入 `node.detail`。本质是"调研 + 结构化"，产出与本模型一致的图。
- **Mode B 代码执行流**：插桩/追踪。静态（AST + 调用图，会漏运行时分发）与动态（`sys.settrace`/`cProfile`、asyncio 任务日志；多进程需向子进程注入 tracer 才能跨进程串联）结合，产生同一套节点/边图。
- 两类采集器都输出同一 Workflow Graph，差异只在保真度（A 为 agent 最佳推断，B 为事实追踪）。

### 四、存储与视图
- **存储**：全量 graph 落盘——JSON（机读）+ 派生 markdown/mermaid（人读）。保留全部粒度，视图只决定展示多少。
- **视图（详情按需）**：可折叠树——顶层只显入口 + 一级步骤（即"整体执行流"）；展开看子节点，再展开看更细。提供 focus 预设：仅整体 / 全展开。循环、并行用专门标记，可展开并行分叉看各分支。
- **格式优先**：交互式 HTML 或可折叠 `<details>` markdown（GitHub 原生收起）；Mermaid 点击展开能力有限，仅作辅助总览。

### 五、工具编排（模块）
- **采集 + 模型**：`concept_capturer`（结构化追问）、`code_tracer`（静态+动态追踪）、`workflow_graph`（schema + 序列化）。
- **存储 + 视图**：全量持久化；可折叠渲染（带深度预设）。
- **编排层 / CLI**：`wdv capture <source> --mode concept|code --depth N --out graph.json` → `wdv view <graph> --expand <levels>`。

### 关键设计决策（需确认的点）
- 两 case 必须收敛到**同一套 Workflow Graph**，viewer 才能复用；否则要维护两套渲染。
- 概念模式（A）的"全量"依赖 agent 结构化能力，保真度弱于代码追踪（B）；是否要对 A 也引入"引用来源/证据"字段以标注推断强度，待定。
