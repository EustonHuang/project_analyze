# Q2 · 一般流程图包含哪些标记/符号？

## 问题
一般流程图中的标记会包含哪些？例如开始/结束、步骤、条件（if）、循环、递归（如果有的话）等等。

## 回答
通用流程图（ISO 5807 / ANSI 标准）的符号可归为五类；下文同时标注它们与本工具 **Workflow Graph**（`questions/001.md` 的模型）的对应关系。

### 一、基础控制流符号（最常用）
- **起止（圆角矩形 / stadium）**：start / end，流程的入口与出口。
- **处理 / 步骤（矩形）**：一个动作、计算或指令（即模型中的 `action` 节点）。
- **判断 / 条件（菱形）**：if / branch，通常有两个出边（yes / no），对应模型的 `branch` 边。
- **流向线（箭头）**：表达执行顺序与方向（模型的 `next` 边）。

### 二、结构化构造符号
- **循环**：标准画法是用"判断 + 回边箭头"回到循环头；ISO 另有专门 loop 符号（带注解的矩形，标循环条件/次数）。
- **准备 / 初始化（六边形）**：for 循环前置、变量初始化等。
- **预定义处理（双边矩形）**：子程序 / 函数调用，对应模型的 `call` 节点（也是表达**递归**的方式——子程序符号指回自身，或加自引用连接符）。

### 三、I/O 与数据符号
- **输入输出（平行四边形）**：读取 / 打印。
- **数据存储（圆柱体 / 开口矩形）**：数据库或存储。
- **文档（底部波浪矩形）**：生成的文件 / 产出物。

### 四、连接与并发符号
- **连接符（小圆 / 编号）**：同页（on-page）或跨页（off-page）连接，避免箭头交叉。
- **汇合（多入一出）**：多分支汇回一点。
- **并发 / 并行（粗横线 fork–join）**：并行分裂与合并，对应模型的 `parallel-member` 边（即 Q1 中 AI Agent 的并行触发、代码的多线程/多进程）。

### 五、与本项目 Workflow Graph 的对应
通用符号很多，但本工具模型只需收敛为少量 `kind`：`入口 / 触发 / 调用 / 并行分叉 / 循环 / 分支 / IO / 异步任务 / 进程线程`；控制流由边 `type`（`next` / `parallel-member` / `loop-back` / `branch` / `spawn`）表达。渲染层再把精简的 `kind` 映射回上述图形符号（菱形=判断、粗横线=并行等），因此**记时模型精简、展时图形丰富**。

### 需确认的点
- 你的两个 case 是否还需要"文档产出物""数据存储"这两类符号？AI Agent 流通常不需要，但代码流若涉及落盘/读写 DB 则建议保留；这会影响模型 `kind` 的最终清单。
