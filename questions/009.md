# Q9 · 我的 Q5–Q8 是在打地鼠——根因不变式与统一管线

## 问题（用户对回答方式的批评）
用户对 Q5–Q8 的连续回答指出：每来一个新担忧就补一个新机制，正是"头痛医头脚痛医脚"。要求退一步给出统一的根因设计，而非继续堆补丁。

## 回答
承认：Q5–Q8 是同一根因的四种症状，逐条加机制确是打地鼠。下面是收敛后的根因架构。

### 一、诊断与根因
- **共同症状**：Q5 图偏离现实、Q6 置信度标错、Q7 编步骤、Q8 修复方案错——表面四个问题。
- **唯一根因**：内容以**"断言"**方式进入系统（节点是断言的、置信度是断言的、修复是断言的），而非"派生 + 验证"进入。所有失效都是"一条不可验证的断言溜了进来"。
- **根因不变式（一句话）**：
  > 一切进入图 / 置信度 / 修复方案的内容 = **候选** + 可独立复现的**证据 token**；须经一条**与生成器分离**的验证管线；验证不过 → 降级 `unverified`，不进"事实"呈现。

### 二、一条验证管线（生成器哑，验证器为真）
```
生成器(只出候选+挂证据token) → 证据绑定 → 验证器(非LLM,基于trace/源码/仓库真值) → 准入(verified) | 降级(unverified)
```
- 修复方案也是候选，走同一管线：带**可检验预测** → 重跑核对 → 用户确认。
- 生成器保持"哑"：只产生候选并挂证据，**全部判断力交给验证器**，使 agent 可能错的推理不出现在"事实"里。

### 三、它如何一次性消解 Q5–Q8（证明非打地鼠）
- **Q5 偏差**：`traced` 节点由证据 token 构成 = 真实那次运行；无法构造"假 traced"（token 必来自真实 trace）。
- **Q6 假自信**：置信度不是意见，是"证据 token 存在性"的**派生值**——有 token=`traced`，无=`unverified`，算出来的，agent 无法错标。
- **Q7 幻觉 + 打地鼠**：生成器只出候选，验证器（独立）决定准入；无证据节点被管线拒，不用逐点补；修 = 改验证器规则 + 重跑管线，全图一致再生，根因一次修。
- **Q8 错误修复方案**：修复方案本身也是候选，须带可检验预测并过同一管线（重跑核对 + 用户确认）；看似对实则站不住 → 预测失败被拒，不静默应用。

### 四、操作纪律 + pivot 到 architecture
- **新失效模式先归类**：任何新发现先问"它违反哪条不变式 / 属管线哪段？"——多数落到"证据缺失"或"验证器规则不足"两类，对应改验证器，不堆新机制。
- **Q5–Q8 降级为验收标准**：其逐条机制不再是独立补丁，而是这条不变式 + 管线的**子节 / 验收条件**。
- **pivot**：本问答应成为 `architecture/001.md` 的核心（Q1 产品设想、Q2–Q4 符号与实例、Q5–Q8 可信度探索在此收敛）。下一步落架构文档，而非再开 questions。
