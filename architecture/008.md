# architecture/008: agent-trace-view 流程图修复与 trace 来源精确化

## 背景

`agent-trace-view` 渲染 `project_analyze_flow.json` 时存在两类严重问题：

1. **流程图为空白**：点击「流程图」后只弹出白色覆盖层，看不到任何节点、边或拓扑关系。根因是 `#cy` 容器在 `#graphOverlay` 仍处于 `display: none` 时就被 Cytoscape 初始化，导致渲染尺寸为 0×0；同时节点标签里塞入来源路径，进一步让图布局崩掉。
2. **来源高亮不准**：大量节点的 `source.line_start/line_end` 指向 YAML frontmatter、模块 docstring 或功能描述，而不是真正被执行的代码。例如 `n4` 进入 history 强制门高亮的是 `"Designed to be driven by CodeBuddy Hooks:"` 这段说明，而不是 `turn_gate.py` 实际执行 `exit 2` 的 `cmd_end` 函数。

## 方案

### 1. 修复流程图渲染

前端 `app.js` 做以下改动：

- **延迟渲染到布局完成后**：`openGraph()` 给 overlay 加上 `.open` 后，使用 `requestAnimationFrame` 再调用 `renderGraph()`，确保 `#cy` 已获得实际宽高。
- **节点标签不带来源路径**：图节点标签只显示 `label`（或 `kind`），不再拼接 `source.path`；避免路径中的 `\n`、长字符串导致 Cytoscape 布局异常。来源路径仍保留在左栏行尾和点击后的 Source Inspector 中。
- **合并样式块**：把 `SHAPE_BY_KIND` 与 `COLOR_BY_KIND` 合并成每个 kind 一个样式块，避免同一 selector 出现两次。
- **增加 resize 与重绘**：渲染后调用 `cy.resize()` 与 `cy.fit()`；监听窗口 resize 时若图处于打开状态则 `cy.resize()`。
- **保留 fallback**：CDN 不可用时仍显示文字拓扑。

### 2. 精确化 trace 来源行号

重写 `agent_traces/project_analyze_flow.json`，原则：**每个 `file` 类型的 source 必须指向可执行/可动作的代码或配置项，而非描述性文字**。典型修正：

- **SKILL.md**：不再指 frontmatter 的 `name/description`，而是指向具体「步骤」「用法」正文（如 agent-trace 的 34–40 行、agent-trace-view 的 9–14 行）。
- **`.codebuddy/settings.json`**：指向具体 hook 的命令块（UserPromptSubmit 3–13、PostToolUse 14–25、Stop 26–36）。
- **`.plan-standard/scripts/turn_gate.py`**：「history 强制门」指向 `cmd_end` 中 `exit 2` 的逻辑（395–423 行），而不是 5–9 行的 docstring。
- **`.plan-standard/scripts/append_history.py`**：指向实际 sub-command 入口或用法示例，而非模块 docstring。
- **`.codebuddy/rules/ai-project-standard/RULE.mdc`**：保留指向受管文件列表等规则正文。

### 3. 明确 parallel / sequence 语义

`project_analyze_flow.json` 本身已在每个 phase 标注 `kind: parallel | sequence`。viewer 左栏的 phase badge 继续显示 `parallel` / `sequence`；流程图里并行阶段的节点彼此无边，顺序阶段形成链式边，布局自然区分。

## 验收标准

1. 点击「流程图」后覆盖层内正确显示全部节点、边、决策分支 yes/no 标签，不再空白。
2. 选中 `n4 进入 history 强制门` 时，右栏高亮 `turn_gate.py` 的 `cmd_end` 实际逻辑，而不是模块 docstring。
3. 所有 SKILL.md 节点的 source 指向具体步骤/用法正文，而非 frontmatter 描述。
4. `validate.py agent_traces/project_analyze_flow.json` 通过。

## 交付物

3. `agent_traces/project_analyze_flow.json`：来源行号全部精确到实际代码/配置。
