# Agent 项目追踪方案

## 目标
只做 **Agent 项目追踪**（代码执行追踪本期不做）。把一个 AI Agent 的"运行过程"拆解成可读、可下钻的追踪文档：从入口 prompt 开始，记录它触发了哪些组件、每一步怎么走，让用户彻底、系统地搞懂"这个 agent 到底怎么运作的"。

## 核心原则
- **capture-max / render-on-demand**：记的时候尽量全（每个触发条件、每一步、并行/循环都记），展示时按需展开。
- **depth 控详略**：记与展解耦。采集按 `depth` 控制下钻层数；渲染时顶层只给"整体执行流"，细节折叠让用户逐级展开或一键 `--expand N` 全开。

## 追踪数据模型
一次追踪 `trace` = `{ entry, triggers[], flow[], depth }`
- `entry`：入口 prompt 原文。
- `triggers[]`：`{ type: rule|memory|hook|skill|tool, name, cond(触发条件), effect(导致什么) }`。
- `flow[]`：执行流树，节点 `node = { id, kind, label, detail, children[] }`。
  - `kind ∈ entry | trigger | step | parallel | loop | branch | async | spawn | io`
  - parallel：children 为并行成员（无先后顺序）
  - loop：children 执行完 loop-back 回本节点
  - branch：children 为各分支（条件择一）
  - async / spawn：children 为并发任务（异步 / 新进程或子 agent）
  - io：读写文件 / 调外部接口
  - step：普通顺序步骤

## 采集方式（agent 流）
不接任何运行时插桩，由 agent（或用户）基于已知信息**结构化讲述/推断**产出 trace：
1. 确定入口：用户那条 prompt → `entry`。
2. 列触发：每条写 type / name / 触发条件 / 效果。
3. 走执行流：按时间/逻辑顺序列步骤；遇并行、循环、分支、异步就换对应 `kind` 节点并递归 `children`。
4. 设 `depth`（默认 3）：记全，渲染再折叠。

## 输入：如何指定要 trace 的对象
统一先收敛成一份 `trace-input`，再由采集器按 `depth` 展开：

1. **自然语言请求（默认）**：在会话里调用 `agent-trace` skill——如 `/agent-trace trace agent-trace-skill` 或自然语言"记录这次运行"。系统据此定位目标（skill 名 / 当前会话 / 某项目），进入采集。
2. **目标引用 reference**：指向具体产物——会话 transcript 文件路径、项目目录、agent/skill 定义文件、或一段粘贴文本。例：`trace --target .codebuddy/skills/agent-trace` 或上传/粘贴 transcript。
3. **实时模式 live（后续版本）**：用户在会话里说"开始 trace"，本会话后续 prompt→触发→步骤被实时记录（需 hook/插桩；本期 agent 流先做结构化讲述版）。

采集器拿到 `trace-input` 后，按 `depth` 做结构化下钻（可交互追问 / 可静默推断），产出 trace JSON 落盘为“养料文件”；渲染由独立的 `agent-trace-view` skill 负责。

## 存储与渲染
### 存储（数据层）
- trace 以**结构化 JSON** 落盘（即上文数据模型），作为单一可信源与“养料文件”；存储只存数据，不存渲染形态。
- 持久化：先期 `agent_traces/<id>.json` 文件；规模上来换 SQLite（按 trace id 索引，节点可独立查询）。

### 渲染（独立 viewer skill）
- 渲染与采集**解耦**：采集侧只产出 trace JSON；渲染由独立的 `agent-trace-view` skill 负责，启动前后端 viewer 读取 JSON 渲染。
- 后端：轻量服务（FastAPI/Flask 或 Node）读取 trace 存储，提供：
  - `GET /traces`、`GET /traces/<id>` 取全量；
  - `GET /traces/<id>?depth=N&kinds=parallel,loop` 按深度/类型过滤；
  - `GET /traces/<id>/search?q=` 节点检索。
- 前端（主视图）：交互式——图视图（React Flow/Cytoscape，缩放/平移/拖拽）、可折叠树、控制条（depth 滑块 + kind 过滤 + 搜索）、详情面板、入口+触发置顶。mermaid 仅作静态导出/兜底。

## 交付物
两个互相解耦的 skill，以 trace JSON 为契约边界：

- **`agent-trace`（采集侧）**：在会话里调用，按"输入"节指定目标，产出 trace JSON（养料文件）落盘到 `agent_traces/`。不启动任何服务、不负责渲染。
- **`agent-trace-view`（渲染侧）**：独立 skill，启动前后端 viewer，读取 trace JSON 渲染成交互视图；与采集解耦，可单独对任意已有 trace 文件使用。

trace JSON 是两者之间的唯一接口：采集只写、渲染只读。

## 待定项
- 输入主用哪种：自然语言请求 / 目标引用 / 两者组合。
- viewer skill 启动方式：内联启本地服务+开浏览器 vs 独立部署服务。
- 技术栈：后端 FastAPI vs Node；前端 React Flow vs Cytoscape。
- 本期仍只做 agent 流。

## 本期不做（deferred）
- 代码执行追踪（静态 AST / 动态插桩 / 多进程追踪）。
- 概念流与代码流统一到同一 viewer（等代码流做出来再合并）。
