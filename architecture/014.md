# architecture/014 · 从根因修正 trace 格式：改 agent-trace skill + 修查看器高亮

> 之前多次手动改写 `project_analyze_flow.json` 是治标——该 JSON 本应由 `agent-trace` skill 产出，而 skill 自身把格式定义成了 `phases[] / conditions[] / yes_branch / no_branch`（见 `SKILL.md:13-24` 与 `trace_template.md`）。本方案从根因修：改 skill 输出契约 + 修文件查看器高亮断裂 + 按新格式产出详细 trace。

## 一、根因诊断
- **格式根因在 skill**：`agent-trace/SKILL.md` 与 `references/trace_template.md` 规定 trace 必须含顶层 `phases[]` + `conditions[]`，`decision` 用 `yes_branch`/`no_branch`，节点类型含 `entry/exit/step/parallel/loop`；`scripts/validate.py` 只校验 `phases`(workflow) 与 `flow`(legacy) 两种旧模型。手改单个 JSON 只会让同一缺陷反复复发。
- **查看器高亮根因在 CSS**：`.file-line.target` 黄色背景只覆盖容器视口宽度；长来源行（如 `settings.json` 命令串）横向滚动时超出部分失去高亮，看起来「中断」。

## 二、修正方案（三处根因）
### 2.1 改 agent-trace skill 输出契约
- `SKILL.md`：删除 `agent_system_workflow` 旧模型（`phases[]`/``conditions[]`/`yes_branch`/`no_branch`），统一为极简 `nodes` 模型；`references/trace_template.md` 重写为 `nodes`+`next` 模板；`scripts/validate.py` 新增 `nodes` 模型校验（取代对 `phases`/`flow` 的强制）。
- 节点仅 `kind`（`start`/`process`/`decision`/`end`）+ `content` + `next`（string=顺序／array=分支·并行·循环带 `label`）+ `source`（file 行号 / system_prompt section）。`source` 仍强制，禁止 `inferred`。

### 2.2 修文件查看器高亮断裂
- `agent-trace-view/web/styles.css`：让 `.file-raw` 随内容宽度扩展成 `inline-block; min-width:100%`，`.file-line` 撑满父宽，使 `.file-line.target` 黄色背景覆盖整行（含横向溢出），滚动不中断。

### 2.3 用新格式产出详细 trace
- 按修正后的 skill 契约，把 `project_analyze_flow.json` 重写为 22 节点通用工作流（含 turn_gate begin/record/end 全细节），作为新格式的范例产出物（而非手补旧格式）。

## 三、极简模型与节点清单
### 3.1 nodes + next 契约
```json
{ "meta": { "kind": "agent_workflow" },
  "nodes": [
    { "id": "1", "kind": "start", "content": "...", "next": "2",
      "source": { "type": "file", "path": "...", "line_start": 6, "line_end": 10, "quote": "..." } },
    { "id": "3", "kind": "decision", "content": "...",
      "next": [ { "to": "4", "label": "yes" }, { "to": "6", "label": "no" } ],
      "source": { "type": "file", "path": "...", "line_start": 0, "line_end": 0, "quote": "..." } }
  ] }
```
- `next` 为 string=单一后继；为 array=多后继（分支/并行/循环），每项 `{to, label}`；循环即 `to` 指向上游 id。

### 3.2 通用工作流节点（22 节点，分组）
- **启动与纪律注入（1–4）**：1 接收 prompt〔start〕；2 turn_gate begin 建 session state〔process〕；3 注入 workspace rule〔process〕；4 解析意图〔process〕。
- **方案门（5–7）**：5 涉及方案改进/新功能/架构？→yes:6/no:8〔decision〕；6 先写方案交评审〔process〕；7 用户批准 implement？→yes:8/no:22〔decision〕。
- **执行与 turn_gate 登记（8–12）**：8 执行交付物〔process〕；9 PostToolUse→record 登记受管文件〔process〕；10 写的是 architecture md？→yes:11/no:12〔decision〕；11 structure_lint 非阻断〔process〕；12 custom feature 则同步 index+TOC 并加入 declared〔process〕。
- **留痕/索引/发布（13–16）**：13 本轮是否改受管文件？（仅此处一次）→yes:14/no:18〔decision〕；14 写 history 事件〔process〕；15 重建索引与 TOC〔process〕；16 set-implemented+commit→push→tag〔process〕。
- **end gate 与阻断补录（17–22）**：17 turn_gate end 比对 declared 与 event_id>baseline 的 target_files〔process〕；18 通过？→yes:22/no:19〔decision〕；19 补录缺失 history〔process〕；20 重 commit/push/tag〔process〕；21 重跑 turn_gate end→18〔process〕；22 结束放行〔end〕。

## 四、验收
- [ ] `agent-trace` skill 文档/模板/校验均只认 `nodes`+`next` 模型，旧 `phases`/`flow` 模型不再被强制执行。
- [ ] `validate.py` 对 `project_analyze_flow.json` 通过（新 `nodes` 模型）。
- [ ] 文件查看器长行横向滚动时 `.file-line.target` 高亮完整不中断。
- [ ] `project_analyze_flow.json` 无 `phases`/`conditions`，节点仅含 kind/content/next(+source)，turn_gate 细节完整。
