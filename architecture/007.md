# architecture/007: agent-trace-view 默认 trace 与相对路径来源修复

## 背景

`agent-trace-view` 启动后存在两个体验问题：

1. **默认 trace 不对**：`/api/traces` 按字母排序返回，`agent_system_workflow.json` 始终排在 `project_analyze_flow.json` 前面，刷新后左侧先显示通用 workflow，而不是当前项目实例。
2. **相对路径来源读不到**：`project_analyze_flow.json` 中大量节点 source 是相对路径（如 `.codebuddy/settings.json`）。server 的 `/api/file` 以 `os.getcwd()` 为根解析，而实际启动目录是 skill 目录，导致右栏显示「读取失败：not found」。

## 方案

### 1. 项目根目录与默认 trace 配置

server 增加运行时配置：

- **新增 `--project-root` CLI 参数**：未指定时默认取 `--trace-dir` 的父目录。例如 `agent_traces` 位于 `/Users/euston/personal/project_analyze/agent_traces`，则项目根为 `/Users/euston/personal/project_analyze`。
- **新增 `/api/config` 接口**：返回 `{ project_root, default_trace }`。
  - `default_trace` 优先取 CLI 参数 `--default-trace`；未指定时按规则匹配：若目录中存在 `project_analyze_flow.json` 则选它，否则回退到字典序第一个 `.json` trace。

### 2. `/api/file` 使用项目根目录解析相对路径

将 `api_file` 中的 `root = os.path.normpath(os.getcwd())` 改为 `PROJECT_ROOT`。相对路径统一以项目根为基准解析，并保留目录穿越校验。

### 3. 前端使用配置

- `loadList()` 先请求 `/api/config`，再请求 `/api/traces`；根据 `default_trace` 设置 `<select>` 默认值，然后加载对应 trace。
- `renderSource()` 中硬编码的 `/Users/euston/personal/project_analyze/` 前缀改为读取 `/api/config` 的 `project_root`，使「在 IDE 打开」链接在不同项目/机器上都正确。

## 验收标准

1. 刷新 `http://127.0.0.1:8765` 后，默认加载并显示 `project_analyze_flow.json`，左侧不再先出现 `agent_system_workflow.json`。
2. 选中 `.codebuddy/settings.json` 来源节点，右栏正确显示文件全文，不再报「读取失败：not found」。
3. IDE 打开链接使用动态 project_root，不再依赖硬编码路径。
4. `validate.py` 通过。

## 交付物

1. `architecture/007.md`（本文件）。
2. `agent-trace-view/server/server.py`：新增 `--project-root`、`--default-trace`、 `/api/config`、修复 `/api/file` 路径解析。
3. `agent-trace-view/web/app.js`：使用 `/api/config` 设置默认 trace 与 IDE 链接前缀。
