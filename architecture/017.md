# architecture/017 · 全局变量挖到底 + 注入节点整文件定位 + 注入步骤完整展开

> 在 architecture/016「每个自定义函数都是节点」之上补齐三类缺口：函数内部引用的全局变量、注入类步骤的来源定位、rule 注入步骤的子步骤展开。

## 一、全局变量也是 trace 节点

### 1.1 定义（不依赖命名风格）
- **全局变量 = 模块顶层赋值的名字**，按赋值位置判定；是否全大写只是常见惯例，不是判据。
- `import` 引入的名字（`os` / `json` / `re` / `subprocess`）是库绑定，不展开。
- 判据是**本次执行路径是否读取**：被某个已展开函数读取的全局变量，必须在该函数节点下嵌套一个定义节点；从未被触达的全局量不设节点（属死代码，应清理代码，而非省略 trace）。

### 1.2 展开规则
- 全局变量节点 `kind=process`，content 标注名字与用途，source 指向模块顶层赋值行。
- 同一全局变量被多个函数引用时，在每个引用者下都出现（与 016 的 `state_path()` 重复展开同规则）。

## 二、注入类节点的定位逻辑

- **「把文件全文注入上下文」的步骤**：source = 整个文件（`line_start=1`、`line_end=末行`）。注入什么定位什么——workspace rule 注入节点定位 `RULE.mdc` 1–18 全文，而非其中一个小节。
- **「读文件某个区间」的步骤**：source = 被读区间。如「先读 README.md 的 MANDATORY 节」定位 `README.md` 72–88。
- **规则文件内的单条要求**：以所在行单行定位，作为注入节点的子节点（父=全文注入，子=具体条目）。

## 三、注入步骤的完整展开

### 3.1 user-level rule 同样注入
- 除 workspace rule 外，user-level rule（跨项目全局纪律）随会话自动注入，必须成节点；其存放于项目之外，source 用 `system_prompt` 类型（section + 原文）。
- 本项目当前 4 条：B+树式点数纪律、禁止澄清式旁白+编号顺排、No Meta-Descriptions、Plan-First。

### 3.2 workspace rule 注入后的必读子步骤
- 注入 `RULE.mdc` 全文后，其「必读与必做」三条逐条成子节点：
  - 读 `<project>/.plan-standard/README.md`「MANDATORY」节（72–88）与 `references/workflow.md`；
  - 任何改动必须在 `history/` 留痕（双录：提问写 `questions/` + 追加 `qna_recorded`；改进进 `improvements/`）；
  - 本规则新会话自动注入，刚安装/升级需新建对话会话生效。
