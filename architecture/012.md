# architecture/012 · 极简 trace 模型与流程图设计

> 依据本轮对 `project_analyze_flow.json` 的全部批评重做。核心约束：**不要有多余的设计**。

## 一、被推翻的旧设计（及其问题）

| 旧元素 | 问题 |
|--------|------|
| `phases` 顶层分组数组 | **冗余**。节点 + `children`/`yes_branch`/`no_branch` 已完整编码控制流；`phases` 是平行的第二套结构，与边图无一致性约束，且实现里被割裂（只喂左树、不进流程图）。 |
| `children` / `yes_branch` / `no_branch` 三套后继字段 | **过度设计**。本质都是「后继节点」，却拆成三种字段名，导致理解混乱（曾把 `children` 误当层级父子）。 |
| `conditions` / `assumptions` 顶层数组 | **冗余**。决策问题已在 decision 节点的 `content` 里；assumptions 可并入普通节点。 |
| 节点 `id` 塞类型前缀（`s1/n1`）、`label`+`detail` 双字段、嵌套 `source` 对象 | 命名暗示假层级；字段冗余。 |

## 二、新模型（强制最小集）

一个 trace 只有两层：

```
meta: { kind, project, standard_version, note, created_at }
nodes: [ Node, ... ]
```

**Node 只含三要素（+ 来源可追溯）：**

```json
{
  "id": "1",
  "kind": "start | process | decision | end",
  "content": "这步干什么（可多行：第一行标题，其后为细节）",
  "next": "2" | [ { "to": "4", "label": "yes" }, { "to": "5", "label": "no" } ] | null,
  "source": { "type": "file", "path": "...", "line_start": 6, "line_end": 10, "quote": "..." }
}
```

- **`kind`**：闭集 `{start, process, decision, end}`。并行 / 循环不另设 kind，用 `next` 表达。
- **`content`**：人类可读的步骤内容。替代旧的 `label`+`detail`。
- **`next`（后继）**：
  - 字符串 → 单一顺序后继；
  - 数组 → 多后继，每项带 `label`（`yes`/`no` 为分支，无 label 或 `parallel` 为并行分叉）；
  - `to` 指向已有节点 id → 即循环 / 回边；
  - `null` → 终点。
- **`source`**：项目强制的**来源可追溯**（architecture/003、/004）。这是项目存在意义，不是过度设计；保留 `{path, line_start, line_end, quote}`，仅此一种来源类型（本 trace 全是 file）。

**由此可完整构建流程图**：每个节点的 `kind` 决定图形符号，`content` 决定文字，`next` 决定全部边（顺序 / 分支 / 并行 / 循环）。无需 `phases` 等任何外层结构。

## 三、流程图（agent-trace-view）设计约束

1. **数据契约**：viewer 只读 `trace.nodes`；`buildGraph` 由 `node.next` 生成边（串行为单线、数组为分支/并行、自指/回指为循环）。**不再读 `phases`**。
2. **左栏**：扁平节点列表（不再按 phase 分组）；`content` 首行作标题，decision 显示 `yes/no` 目标。
3. **中栏**：选中节点的 `content` + `source`（path:行号 可点开 IDE）。
4. **右栏**：文件查看器，定位到 `source` 行号。
5. **图视图**：Cytoscape 渲染，`kind` 映射形状（start/end=圆角矩形，process=矩形，decision=菱形）；完整展开全部节点与边，不做层级折叠。

## 四、验收

- [ ] trace 文件无 `phases` / `conditions` / `assumptions` / `children` / `yes_branch` / `no_branch`。
- [ ] 每个节点仅含 `kind` / `content` / `next`（+ `source`）。
- [ ] viewer 由 `nodes` + `next` 重构图，无 phase 逻辑。
- [ ] 流程图可完整呈现顺序 / 分支 / 并行 / 循环。
