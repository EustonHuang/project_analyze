# agent-trace-view 渲染侧修复方案

## 问题来源
- Q13（history/022）：viewer 访问 `http://127.0.0.1:8765` 返回 404。`server.py` 第 15 行 `WEB = os.path.join(ROOT, "web")` 把前端目录算成 `server/web/`，而前端实际位于 `server/` 同级的 `agent-trace-view/web/`，`SimpleHTTPRequestHandler` 从不存在的目录取文件 → 404。
- Q14（history/023）：调用 skill 后 server 前台 `serve_forever()` 阻塞命令行，只能强杀才能继续。

## 修复设计
### WEB 路径修正（Q13）
- 根因：`ROOT = dirname(server.py)` 即 `server/` 目录，`WEB` 由此拼出 `server/web/`，与前端真实位置（`agent-trace-view/web/`）差一层。
- 方案：改为 `WEB = os.path.join(os.path.dirname(ROOT), "web")`（取 `server/` 的父目录再拼 `web`），或用 `Path(__file__).resolve().parent.parent / "web"`。前端文件 `index.html / styles.css / app.js` 不动。

### server 前台阻塞（Q14）
- 根因：`HTTPServer((host, port), Handler).serve_forever()` 是阻塞调用，作为前台 CLI 命令执行时永久占住命令行。
- 方案（组合采用）：
  - 启动命令改为后台/分离运行（`nohup python3 ... &` 或 `setsid`），释放命令行；
  - server 内加空闲看门狗：超过阈值（如 10 分钟无请求）自动 `shutdown()` 自退；
  - 提供 `--stop` 指令 + PID 文件，支持干净退出。
- 文档：`SKILL.md` 启动说明写清「后台启动 + 如何停止」，避免用户只能强杀。

## 验收标准
- 启动后浏览器访问根路径返回 200 并渲染 viewer（不再 404）。
- server 在后台运行，命令行不被占住，且可显式停止。
- `python3 server/server.py --trace-dir agent_traces --port 8765` 端到端跑通，`/api/traces` 返回现有 `example.json`。

## 不做项
- 不改动数据模型、采集侧（`agent-trace`）、前端 `app.js / index.html / styles.css`。
- 不引入第三方依赖，保持 stdlib 零依赖。
