# architecture/015 · trace 到底：把关键 helper 函数也展开为节点

> 在 architecture/014 根因修复基础上，继续细化：用户指出 `cmd_begin` 只 trace 到入口，里面的 `save_state()` 没出现。本方案让 `agent-trace` skill 明确要求——追踪一个命令时，必须继续追踪其内部对流程状态有实质影响的关键 helper 调用。

## 一、问题
014 产出的 trace 中，`turn_gate begin` 只表现为一个节点：

> 「创建 session state（session_id + baseline_max_id + declared=[]）」

但 `cmd_begin()` 内部真实执行了三件事：
1. `session_id()` —— 确定当前会话标识（env 或 pid）。
2. `baseline_max_id()` —— 读取 `history_index.json` 的 `max_id`。
3. `save_state(state)` —— 原子写入 `.codebuddy/hooks/.turn/<session>.json`。

只画入口，等于把命令当黑盒；用户横向对比源码时会发现 trace 缺了一段。

## 二、修正方案
### 2.1 改 agent-trace skill：新增「trace 到底」原则
- `SKILL.md` 增加一节：追踪一个顶层命令/动作时，若其内部调用了对流程状态有实质影响的 helper（如创建文件、读写状态、过滤路径、扫描目录），必须把这些 helper 也作为 `process` 节点展开，并指向 helper 函数的真实行号。
- `references/trace_template.md` 增加示例：在 `turn_gate begin` 入口后展开 `session_id()` / `baseline_max_id()` / `save_state()` 三个 `process` 节点。
- `validate.py` 保持不变（已支持 `nodes` 模型）。

### 2.2 用新原则重写 project_analyze_flow.json
- 把 `turn_gate begin` 展开为 4 个节点：入口 → `session_id()` → `baseline_max_id()` → `save_state()`。
- 把 `turn_gate record` 适度展开：`load_state()` → 提取 filepath → `in_plan`/`norm_rel`/`is_ignored` → 保存/同步。
- 把 `turn_gate end` 适度展开：`load_state()` → `_new_event_targets()` → 判定。
- 总节点控制在 25 个以内，仍符合 B+ 树式文档纪律。

## 三、极简模型（沿用 014）
节点仅 `kind`（`start`/`process`/`decision`/`end`）+ `content` + `next` + `source`。helper 函数节点 kind 统一为 `process`。

## 四、通用工作流节点（25 节点，分组）
- **4.1 入口与 turn_gate begin（1–5）**：1 接收 prompt〔start〕；2 turn_gate begin 入口〔process〕；3 `session_id()`〔process〕；4 `baseline_max_id()`〔process〕；5 `save_state(state)` + 输出基线〔process〕。
- **4.2 纪律与方案门（6–10）**：6 注入 rule〔process〕；7 解析意图〔process〕；8 涉及方案/新功能/架构？→yes:9/no:11〔decision〕；9 先写方案交评审〔process〕；10 用户批准？→yes:11/no:25〔decision〕。
- **4.3 执行与 turn_gate record（11–15）**：11 执行交付物〔process〕；12 turn_gate record 入口〔process〕；13 `load_state()` + 提取 filepath〔process〕；14 `in_plan`/`norm_rel`/`is_ignored`〔process〕；15 保存 state + custom 同步〔process〕。
- **4.4 留痕与发布（16–19）**：16 本轮改受管文件？→yes:17/no:20〔decision〕；17 写 history 事件〔process〕；18 重建索引与 TOC〔process〕；19 commit→push→tag〔process〕。
- **4.5 end gate 与放行（20–25）**：20 turn_gate end 入口〔process〕；21 `load_state()`〔process〕；22 `_new_event_targets()`〔process〕；23 通过？→yes:25/no:24〔decision〕；24 补录缺失 history〔process〕；25 结束放行〔end〕（重新校验由 24→20 循环处理）。
