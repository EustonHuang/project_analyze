# architecture/016 · 每个自定义函数都是节点 + 展开/折叠

> 在 014/015 根因修复基础上继续收敛用户的两个硬要求：(1) **trace 到底**——只展开到 `save_state` 还不够，`save_state` 内部调用的 `state_path()`（以及 `turn_gate.py` 里每一个自定义函数）都必须有节点；(2) **展开/折叠**——默认只看总体步骤，点一下才深入 helper，用户自己决定看整体还是看细节。

## 一、问题
- 015 只展开到 `save_state`，漏了它内部的 `state_path()`。用户的规则是：只要是你自己写的函数，**每个都要有节点**；库内部函数（如 `pandas.read_csv`、`os.path.join`）不查。若函数太多，那是代码抽象太多的问题，该删函数，不是该省 trace。
- 之前没有展开/折叠：几百个节点一展开就糊成一片，但用户要的是「总体步骤 ↔ 深入细节」按需切换。

## 二、修正方案
### 2.1 数据模型：node 可嵌套 `nodes`（children）
- 顶层 `nodes[]`；每个节点可含 `nodes[]`（子步骤，递归）。`next` 仍是同层后继；嵌套子节点用 `next` 串接，最后一个子节点 `next` 为 `null` 时回落到父节点的 `next`。
- 无 `phases` / `conditions` / `yes_branch` / `no_branch` / `children`（顶层/分支字段仍用 `next` 表达）。

### 2.2 agent-trace skill 新增两条硬规则
- **完整性**：追一个命令时，把它执行路径上**所有自定义函数**都列为节点（含库调用链上的自定义 helper）；库内部函数不展开。若某自定义函数从不被执行路径触达，则视为死代码，应删除以收敛规模，而非省略 trace。
- **可折叠**：默认只渲染顶层节点（总体步骤）；含 `nodes[]` 的节点带折叠标记，点一下展开其 children，再点收起。

### 2.3 viewer：展开/折叠
- 左栏渲染为**树**（带 ▸/▾），点击 caret 切换展开；右图按当前展开状态重建（展开时父节点被 children 替换，首 child 承接入边、末 child 出边回落到父 `next`）。
- 图中点击含子节点的节点同样切换展开。

### 2.4 trace：turn_gate.py 全程展开
- `cmd_begin` → `session_id()` / `baseline_max_id()` / `save_state()`（→ `state_path()`）/ print。
- `cmd_record` → `load_state()`（→ `state_path()`）、`read_stdin_json()`、`extract_filepath()`、`in_plan()`、`norm_rel()`、`is_ignored()`（→ `load_turngateignore_lines()` / `_glob_translate()` / `_pattern_matches()`）、`custom_feature_of()` / `registered_custom_features()` / `sync_custom_feature()` / `custom_side_files()`、`save_state()`（→ `state_path()`）、`_run_structure_lint()`。
- `cmd_end` → `load_state()`（→ `state_path()`）、`_new_event_targets()`（→ `norm_rel()`）、判定。

## 三、极简模型（沿用 014/015）
节点仅 `kind`（start/process/decision/end）+ `content` + `next` + `source`；helper 统一 `process`；可嵌套 `nodes[]`。

## 四、验收
- [ ] `project_analyze_flow.json` 通过 `validate.py`（递归校验嵌套 nodes）。
- [ ] `state_path()` 在 `save_state` 与 `load_state` 下均有节点；`turn_gate.py` 执行路径上的自定义函数均无遗漏。
- [ ] viewer 左栏为可折叠树；默认折叠、点 caret/图节点可展开深入，再点收起。
- [ ] 库中函数（os/json/subprocess）不展开。
