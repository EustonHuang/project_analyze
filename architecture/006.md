# architecture/006: agent-trace-view 三栏文件视图与流程图修复

## 背景

viewer（`agent-trace-view`）渲染 `agent_traces/project_analyze_flow.json` 时暴露三类问题：

1. **来源不可读**：Source Inspector 只显示 quote 片段，看不到来源文件全貌；目标行区间不显著；markdown 文件无法在原文与渲染结果之间切换。
2. **布局缺陷**：实际可见区域只有两块，文件内容没有独立展示区。
3. **流程图失效**：「流程图」按钮点击无效果，无法通过图理解 workflow 的步骤走向；另外 phase 编号从 P0 起与「步骤从第 1 步开始」的直觉相悖。

## 方案

### 1. 三栏布局 + 右栏全文件查看器

界面固定为三块：

- **左栏 Phase Navigator**：保持现状（按 phase 分组平铺、只看决策、搜索）。
- **中栏 Source Inspector**：节点详情与 quote（保持现状）。
- **右栏 File Viewer**：新增。server 增设 `/api/file?path=` 返回整文件文本；前端带行号渲染全文，目标行区间显著高亮并自动滚动定位；头部以 `path : start-end` 形式显示目标区间，保留 IDE 点击链接。

markdown 文件提供 **Raw / Rendered 切换**：默认 Raw（行号与高亮始终可用），Rendered 经 marked.js（CDN，离线时回退 Raw）。

### 2. 流程图修复

失效根因：`setMode` 切换后未重新挂载 `#cy` 容器，且 `render()` 在两种模式下都强制给图面板加 `collapsed`，图永远不可见。

改为独立覆盖层：顶栏「流程图」按钮打开全屏 graph overlay，`#cy` 固定挂在 overlay 内；关闭按钮 / Esc 退出。原「图」按钮与 Anatomy/Flowchart 双模式切换移除，入口统一为一个「流程图」按钮；点击图节点仍联动中栏详情与右栏文件。

### 3. 阶段编号从 1 起

- **数据侧**：trace 的 `phases[].id` 从 `P1` 起编号（`project_analyze_flow.json` 由 P0–P4 重编为 P1–P5）；agent-trace 采集约定同步注明。
- **渲染侧**：Nav 标题按顺序显示 `P{index+1}`，与存储 id 解耦，历史 trace 中的 0 起编号也不再外显。

## 验收标准

1. 选中任一 `file` 来源节点，右栏显示整个文件（带行号），目标区间高亮且自动滚动到可见；头部显示 `path : start-end`。
2. `.md` 来源可在 Raw / Rendered 间切换，两种视图对应同一文件。
3. 点击「流程图」立即出现全屏流程图（形状映射不变），可关闭；选中图节点联动详情。
4. 左侧 phase 标题从 P1 起；`project_analyze_flow.json` 中无 P0。
5. `validate.py` 通过。

## 交付物

4. `agent-trace-view/SKILL.md`、`agent-trace/SKILL.md`：约定同步。
5. `agent_traces/project_analyze_flow.json`：phase 重编号。
